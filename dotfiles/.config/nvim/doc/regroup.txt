*regroup.txt*   Patch review and landing over dienpy hunks              *regroup*

The engine runs in the shell (tab-completed): >
    dienpy hunks run [loose|normal|granular] [bare|agents|explore] [profile]
    dienpy hunks list          cached runs + coverage
    dienpy hunks use [dims]    make a cached run the current one
<
Results land in .git/regroup-cache.json. nvim parses no diff and writes no git
state: it reads `hunks list --json` and every action below is a `hunks patch`,
`hunks branch`, `hunks graveyard` or `hunks run --extend` call on the run it is
showing (the engine is re-pointed at that run first whenever a shell moved it).

A patch is a set of hunks with a commit title and message. Every patch ends
committed on the current branch (<C-y>), committed on a new patch branch
(<C-x>), buried (<C-t>) or discarded (<C-d>). A patch branch is landed as one
squashed commit (<C-l>, or from :RegroupBranches); its history stays under
refs/landed/<name>, never pushed.

The session navigates on its last listing; a save, a git command or a focus
change refreshes it in the background, an engine write refreshes it at once.

EDITING WHILE REVIEWING                                        *regroup-edit*
Fixing something inside a hunk changes its id: the hunk leaves its patch and
shows up under "(unassigned new changes)". <C-e> has the model place it
(`hunks run --extend`, run async, a notification tells when it is done and
<leader>gg reopens the picker), <C-o> in the hunk picker moves it by hand.
Or commit the patch first and fix on the branch — the landing squashes it.

GLOBAL                                                         *regroup-keys*
    <leader>gg    patch picker at last position; run list when no session
    <leader>gG    run picker                                  :RegroupRuns
    ]g  [g        next / prev hunk in the current patch
    ]G  [G        next / prev patch
    :Regroup granular sonnet             narrow to one cached run, any order
                                         (completes from the cached keys)
    :RegroupBranches                     patch branches
    :RegroupGraveyard                    buried patches

EVERY PICKER                            (? in normal mode lists all keys)
    <C-j> / <C-k>  scroll the preview down / up half a page

RUN PICKER
    <CR>  review this run    <C-e>  extend it
    <C-t>  graveyard         <C-x>  patch branches

PATCH PICKER                            (<Tab> marks several, one engine call)
    <CR>  browse patch
    <C-h>  hunk list
    <C-s> / <C-u> / <C-d>  stage / unstage / discard (revert to HEAD)
    <C-y>  commit on the current branch (:w commits, :q aborts)
    <C-x>  new patch branch from the marked patches (name prompted)
    <C-l>  land the current branch: one squashed commit onto main
    <C-t>  bury →  graveyard
    <C-e>  extend this run (model places the unassigned hunks)

HUNK PICKER
    <CR>  jump    <C-g>  back    <C-s> / <C-u> / <C-d>  same, per hunk
    <C-o>  move this hunk to another patch (persisted to the cache)

PATCH BRANCHES                                            *regroup-branches*
    <CR>  switch to it    <C-l>  land    <C-d>  drop (kept under refs/dropped)

CHANGED-FILE PICKER                              <leader>gf, review mode
    <CR>  open in the review diff    <Right> / <Left>  stage / unstage file
    <C-y>  commit the index, in the same commit buffer as the patch picker

GRAVEYARD                  (regroup-tagged git stashes)  *regroup-graveyard*
    <CR>  restore (pop)    <C-d>  delete forever
